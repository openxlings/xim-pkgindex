# LLVM 23.1.3 on native Linux aarch64

The delivery consists of the `llvm` and `llvm-tools` packages and their Linux
runtime dependencies. The public toolchain coordinate remains
`xim:llvm@23.1.3`. Linux archive names use `aarch64`; macOS archive names retain
`arm64`. Older LLVM releases without an ARM64 archive remain unavailable on
Linux aarch64.

## Runtime and target contracts

The LLVM package contains Clang, LLD, LLVM binary utilities, compiler-rt,
libc++, libc++abi, libunwind, standard library module sources and libatomic.
The tools package contains clang-format, clang-tidy and clangd. LLVM library
registration uses the target directory present in the payload rather than an
x86_64 directory constant. Installation derives payload directories from the
selected archive, including recipe revisions whose version key differs from
the upstream archive version.

The glibc package uses upstream 2.44 and package version 2.44.3 revision 1.
Both architectures retain the reserved relocation prefix, private preload path,
loader-relative default library directory, install-time prefix relocation and
C.UTF-8 generation. The aarch64 runtime exports
`lib/ld-linux-aarch64.so.1`, ABI `linux-aarch64-glibc` and library directory
`lib`. The x86_64 runtime retains its `lib64` layout and ABI. Kernel headers
are installed with `ARCH=arm64`; x86 UAPI headers are not interchangeable.

Linux aarch64 catalog metadata requires xlings 2026.10.8.1 or later. That
client exposes the process architecture while loading catalog recipes and
hooks. Older x86_64 clients retain the existing runtime descriptor. This
client requirement precedes enabling the Linux aarch64 default in mcpp.

The native GNU target and compiler startup are separate contracts. Installing
and starting Clang establishes only compiler startup. C/C++ compilation,
standard library modules, exceptions, threads, atomics and a packed consumer
must additionally resolve headers, CRT objects, loader and shared libraries
from the managed package closure.

## Reproduction

`.agents/tools/build-linux-aarch64-deps.sh` builds Linux 5.11.1 UAPI headers,
zlib 1.3.1, libxml2 2.13.5 and GCC runtime 15.1.0 on a native aarch64 host.
GCC runtime is built from GCC sources; distribution runtime libraries are not
renamed as a newer GCC release. Distribution GCC is a bootstrap input.
Source archive digests and bootstrap identity are recorded in provenance.

The glibc builder supports explicit bootstrap inputs without a pre-existing
SubOS:

```bash
GLIBC_BUILD_ARCH=aarch64 \
GLIBC_BUILD_CC=gcc GLIBC_BUILD_CXX=g++ \
GLIBC_BUILD_HEADERS=/tmp/aarch64-deps/linux-headers-5.11.1-linux-aarch64/include \
XLINGS_GFX_WORK=/tmp/glibc-build \
bash .agents/tools/graphics/build-glibc.sh 2.44 2.44.3 1
```

LLVM is carved from the upstream `LLVM-23.1.3-Linux-ARM64.tar.xz`, extracted
once. Both invocations use the same extracted source directory:

```bash
bash .agents/tools/build-llvm-subpkg.sh --in /tmp/llvm-upstream \
  --pkg llvm --version 23.1.3 --platform linux --arch aarch64 \
  --out /tmp/aarch64-assets
bash .agents/tools/build-llvm-subpkg.sh --in /tmp/llvm-upstream \
  --pkg tools --version 23.1.3 --platform linux --arch aarch64 \
  --out /tmp/aarch64-assets
```

The carve rejects a foreign ELF machine, including an incompatible libatomic
selected from the bootstrap compiler. Shared libraries receive `$ORIGIN`
RUNPATH. Each archive has a SHA256 sidecar. GLOBAL and CN copies must have
identical digests before the corresponding index entries become available.
Existing x86_64 assets remain immutable.

## Acceptance

Recipe tests exercise catalog runtime exports and installation library
registration on both architectures. A synthetic foreign LLVM tools payload
must fail before packaging. Native build and consumer CI establish the
additional runtime evidence: loader/core-libc coherence, private dependency
resolution, modules and consumer execution. Local static tests do not replace
these native gates. Release publication follows complete native verification
and all existing platform checks.
